# Sprint S8 — Persistência e Biblioteca Local

> **Estado:** Em andamento
> **Registro:** contemporâneo
> **Roadmap:** [Sprint 8](../roadmap.md#sprint-8--persistência-e-biblioteca-local)

## Objetivo

Criar a base local-first da biblioteca pessoal sem depender de autenticação ou
backend, definindo os modelos de domínio (`LibraryEntry`, status, progresso,
notas pessoais), a solução de persistência multiplataforma compatível com os
5 targets vigentes (Android, Desktop, iOS, JS e WasmJS), o esquema local, mapeadores
e o `LibraryRepository`.

## Baseline

- As sprints S6 e S7 entregaram busca e detalhes completos de animes consumindo
  a AniList via catálogo, com navegação tipada por `CatalogAnimeId`;
- A tela de biblioteca (`LibraryScreen`) permanece como placeholder sem estado
  ou armazenamento real;
- Não há dependência de banco de dados ou persistência estruturada configurada em
  `gradle/libs.versions.toml`;
- O projeto mantém 5 targets ativos: Android, Desktop/JVM, iOS (Arm64/Simulator),
  JavaScript e WasmJS.

## Auditoria de Persistência Multiplataforma (S8.1)

Como critério eliminatório, a solução de persistência deve operar nos 5 targets ativos do projeto: **Android, Desktop/JVM, iOS, JavaScript e WasmJS**.

### Comparativo técnico

| Critério | Room KMP (2.7+) | SQLDelight (2.0+) | Custom Expect/Actual Local Storage |
|---|---|---|---|
| **Android** | Nativo (SQLite) | Nativo (`AndroidSqliteDriver`) | Nativo (Room/SQLite) |
| **Desktop/JVM** | SQLite com bundled driver | Nativo (`JdbcSqliteDriver`) | JDBC / H2 / SQLite |
| **iOS (Arm64/Simulator)** | Nativo (SQLite) | Nativo (`NativeSqliteDriver`) | CoreData / SQLite |
| **JavaScript** | Sem suporte oficial | Suportado (`WebWorkerDriver` / `sql.js`) | IndexedDB / LocalStorage |
| **WasmJS** | **Incompatível / Sem suporte** | **Experimental / Requer setup WASM SQLite** | **Nativo via IndexedDB / Web Storage API** |

### Decisão Arquitetural de Isolamento

Para garantir que a UI e o Domínio permaneçam completamente desacoplados da implementação física do banco de dados:
1. O domínio consumirá exclusivamente o contrato `LibraryRepository`;
2. A camada de dados conterá uma abstração `LibraryLocalDataSource`;
3. A implementação do armazenamento local encapsula os drivers por plataforma sem vazar tipos ou dependências para `commonMain`;
4. Na S8.2, a estrutura de tabelas/esquema será projetada em conformidade com o driver selecionado, assegurando suporte pleno a WasmJS e JS sem regressões.

## Evidências de validação automatizada (S8.1)

Testes de invariantes implementados em `composeApp/src/commonTest/kotlin/br/com/mykytadu/domain/model/LibraryModelsTest.kt`:
- `LibraryEntryId`: Rejeição de valores em branco; distinção de tipo em relação a `CatalogAnimeId`.
- `LibraryProgress`: Rejeição de `current` ou `total` negativos; cálculo de `isOverTotal`, `clampedCurrent` e `completionRatio`; operações imutáveis `increment()` e `decrement()` com piso zero.
- `LibraryRating`: Validação de intervalo 0..100.
- `LibraryEntry`: Invariante temporal (`updatedAt >= createdAt`), validação de tamanho máximo de notas (`MAX_NOTES_LENGTH = 5000`) e métodos de cópia/atualização imutáveis (`withProgress`, `withStatus`, `withRating`, `withNotes`).

- **JavaScript (`:composeApp:jsBrowserTest`):** 301 testes executados, 0 falhas.

## Decisões consolidadas

- A biblioteca é estritamente **local-first**: leitura e escrita acontecem localmente sem chamadas de rede obrigatórias;
- As regras de transição de status (Planejando, Assistindo, Pausado, Concluído, Abandonado) pertencem ao domínio;
- A chave primária local de uma entrada na biblioteca (`LibraryEntryId`) é independente do `CatalogAnimeId`, embora cada anime no catálogo possa ter no máximo uma entrada associada na biblioteca;
- O suporte a WasmJS e JS é critério eliminatório da persistência física, isolada por `LibraryLocalDataSource`.

## Bloqueios, riscos e mudanças de escopo

- **Persistência em WasmJS:** WasmJS necessita de driver compatível com o navegador (WebWorker/IndexedDB). A camada de dados manterá abstração para permitir drivers adequados sem quebrar os testes dos targets.
- O build nativo iOS continua dependente de ambiente macOS/Xcode, sendo validada a compilação de metadata no ambiente local.
